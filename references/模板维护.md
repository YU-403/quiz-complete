# 模板维护参考

> **本文档只在「需要修改 build.py 模板」时阅读。**
>
> 正常使用本 Skill（出题、建站）**不需要**看这里——以下问题都已在模板中修复，
> 只有当你 fork 模板、自行改动 HTML/CSS/JS 时，才需要留意这些坑。

---

## 一、常见坑与预防

历史上踩过的问题，改模板时容易重犯：

| 问题 | 原因 | 预防 |
|:-----|:-----|:------|
| CSS animation 阻塞 hover | forwards 填充模式持续应用 transform | 所有动画使用 backwards 填充 |
| f-string 模板报错 | JS 代码中的 `{}` 被 Python f-string 误解析 | 用字符串替换注入，不用 f-string |
| 题干解析失败 | 正则只匹配半角括号，中文用全角 | 兼容 `[^)）]*[)）]` |
| 导航按钮未作答可见 | 未检查提交状态 | 提交后才显示导航 |
| 三区块视觉雷同 | 共用同一套样式 | 独立 CSS 类（answer-box / expl-box / tag-box） |
| 题目编号重复 | 同一文件两个「第 N 题」 | 解析时检测重复并警告 |
| 繁简知识回溯不兼容 | 正则只写了一种 | `(?:知识\|知識)回溯` |
| 双源答案不一致 | 加粗标记与答案字段矛盾 | 交叉校验并报警 |
| 多题库进度覆盖 | localStorage key 硬编码 | 文件夹名作前缀隔离 |
| 提交后看不到裁决区 | 区域在屏幕下方 | 自动 scrollIntoView |
| HTML 字符渲染异常 | 被当作标签解析 | esc() 转义 |
| 答对时缺少确认感 | 只显示 ✅ | 答对 / 答错均展示确认条 |
| 题型标签不醒目 | 仅靠文本颜色区分 | 添加 `.q-type` 彩色 Badge（蓝=单选 / 橙=不定项 / 绿=判断） |
| 板块列表无序 | JS 默认按 Unicode 码点排序，中文字顺序错乱 | 用 `localeCompare(b, 'zh-CN')` 按中文语义排序 |
| 取消后不回首页 | 仅关闭弹窗未切换页面 | `cancelTagSelection()` 同时 `showPage('page-home')` |

## 二、稳定 ID 机制

题目 ID 决定用户的刷题进度（作答记录 / 错题池 / 收藏）指向哪道题，改动前务必理解：

- 每道题的 `id` 基于**题干内容哈希**生成（如 `q_a1b2c3d4`），与题目序号无关——
  增删题目、调整顺序均不影响已有进度
- 专题模式进度按 `id` 存储而非数组索引，增删其他板块的题不影响已有进度
- 生涯模式、错题集、随机模式的已做题记录均使用 `id`
- build.py 自动注入版本哈希（md5 摘要），页面加载时对比 localStorage 中保存的哈希值，
  不一致时提示「题库已更新」

**当前算法**：`md5(分节名 + 题干)[:8]`

> ⚠️ 该算法隐含假设「**同一文件内题干不重复**」。若同一文件内出现两道题干相同的题，
> 会生成相同 ID，导致两题共用一条作答记录。
> 构建期的质量自检会检查 ID 唯一性并告警，但**更好的做法是修改哈希输入**
> （如加入选项文本），使唯一性不再依赖「题干不重复」这个前提。

## 三、动画冲突预防（CSS 规则）

改 CSS 动画时遵守以下规则，可避免动画与交互冲突：

1. 所有 `@keyframes` 的 `animation-fill-mode` 使用 `backwards` 而非 `both`
2. 动画的 `from` 关键帧中**不设置 `transform`**，只设 `opacity`
3. 每个 CSS 选择器只定义一次，避免覆盖混乱
4. 所有 `transition` 统一为 `all 0.3s ease`

**为什么**：`forwards` / `both` 填充模式会在动画结束后持续应用最终帧的 `transform`，
从而覆盖 `:hover` 的 `transform: scale(1.04)`——表现为「按钮悬停没有放大效果」。

## 四、质量自检阈值

`build.py` 顶部的 `AUDIT_THRESHOLDS` 定义质量告警阈值，与 `SKILL.md` 的命题底座一一对应。

**调整规范时须同步修改这里**，否则会出现「文档说一套、检查报另一套」的矛盾。

| 阈值键 | 含义 | 当前值 |
|:--|:--|:--|
| `single_pos_max_pct` | 单选单一选项占比上限 | 35% |
| `multi_full_max_pct` | 不定项全选率上限 | 10% |
| `opt_len_gap_max` | 选项字数极差上限 | 6 字 |

## 五、界面文案繁体词表

`build.py` 中的 `_UI_TRAD` 是「简体片段 → 繁体片段」白名单，
用于繁体题库的界面文案转换。

**维护方式**：模板新增界面文案后，把它的**连续汉字片段**补进该表即可。

> ⚠️ **`'正确'` / `'错误'` 不得加入此表。**
> 它们是**内部比较值**——数据由 `normalize_judge_answer()` 生成（恒为简体），
> 模板里 `q.answer === '正确'` 与之比对。若模板侧被转成 `'正確'`，
> 会导致**全部判断题判错**（v2.9 曾发生过此事故）。
> 它们在界面上的显示由 `__JUDGE_TRUE__` / `__JUDGE_FALSE__` 占位符按语体注入。

白名单的失败方向是安全的：漏收某条，最坏只是该处仍显示简体，不会破坏功能。
