# 需求采集与需求文档

> 返回主流程：[`SKILL.md`](../SKILL.md)

本文件只用于首次接收需求和后续需求变更。每次只问一个问题；收到回答后先更新
工作目录根部的 `REQUIREMENTS.md`，再提出下一问。

## 工作目录

第一个问题是本次出题工作的完整工作目录。

- 默认建议：`<当前用户桌面>/QuizComplete-YYYYMMDD`
- 回答前要把日期和完整绝对路径解析出来展示给用户。
- 目录不存在则创建。
- 目录已存在且为空则直接使用。
- 目录已存在且非空时先询问：继续使用、创建子目录或取消。
- 已有 `REQUIREMENTS.md` 时先读取，再询问继续项目、创建子目录或取消。

确认目录后立即创建：

```text
<工作目录>/
├── REQUIREMENTS.md
└── 题库/
```

## 一问一答格式

每个问题必须显示：

1. 当前问题；
2. 可选项；
3. 具体默认值；没有默认值时写“默认：无（必须选择）”；
4. 用户可以自由描述自己的要求，存在默认值时也可以回答“按默认”。

示例：

```text
问题：字体使用简体还是繁体？
默认：简体
可回复：简体 / 繁体 / 你自己的要求 / 按默认
```

用户主动一次回答多项时，全部写入需求文档并跳过已答问题。用户对无默认项回答
“按默认”时，说明该项没有默认值并请用户重新选择。

每个回答写入需求文档后，至少包含：

- 需求 ID；
- 用户原始回答或归一化决定；
- 来源：用户 / 默认值 / 自动推导；
- 状态：待确认 / 已确认 / 已变更 / 不适用；
- 更新时间。

写入失败时停止继续提问。

## 出题问题顺序

| 顺序 | 需求项 | 当前默认值 |
|:--|:--|:--|
| 1 | 工作目录 | 桌面下的 `QuizComplete-YYYYMMDD` |
| 2 | 参考材料路径与格式 | 无（必须选择；PDF/Word/扫描件/Markdown/URL） |
| 3 | 考察范围 | 无（必须选择） |
| 4 | 题型 | 无（必须选择；单选/不定项/判断/简答/辨析等） |
| 5 | 总题量与各题型比例 | 无（必须选择） |
| 6 | 题目单元结构 | 题目 → 答案 → 解析 → 知识回溯 |
| 7 | 是否有样题 / 真题 | 无样题 |
| 8 | 字体偏好 | 简体 |
| 9 | 知识回溯粒度 | 无（必须选择：章级/节级/篇名级/注码级） |
| 10 | 解析风格 | 无（必须选择：简洁/详尽/纯答案无解析） |
| 11 | 学习场景 | 无（必须选择：自习/备考/自测/贴合具体考试） |
| 12 | 难度基线 | 无（必须选择：入门/达标/进阶/以真题为准） |

## 建站问题

只有用户要求建站时，进入阶段二后逐题增加。详细模式与风格见
[`建站指南.md`](建站指南.md)。

| 需求项 | 当前默认值 |
|:--|:--|
| 题库路径 | `<工作目录>/题库` |
| 网站输出目录 | `<工作目录>/网站` |
| 刷题模式 | `topic,random,career,wrong,tag,exam` 六种全开 |
| 题库是否含公式 | 无（必须确认） |
| 视觉风格 | 古朴宣纸风 |
| 网站标题 | 无（必须选择） |
| 审计配置 | 无（使用 build.py 默认阈值） |

建站回答同样追加到 `REQUIREMENTS.md`，使用 W 开头的需求 ID。

## 冻结需求

所有必需问题完成后：

1. 在需求文档生成“当前有效需求”和“验收标准”摘要；
2. 检查缺失项和冲突项；
3. 请用户确认；
4. 将文档状态改为“已冻结”；
5. 冻结后才开始扫描材料和正式出题。

后续需求变化不删除旧记录；创建新版本、写明变更原因，并重新执行受影响的复核。
