# 出题规范

> 返回主流程：[`SKILL.md`](../SKILL.md)

本文件用于材料分析、考法画像、命题、样题校准、题集输出和出题复核。

## 材料与考法画像

### 材料摸底

- 检查材料是否已转为 Markdown 或 JSON。
- 扫描件可调用 MinerU 等 OCR 工具，但需用户确认。
- 材料有明显缺失或错误时，要求用户补充或指定以某份材料为准。
- 无法补充时避开有争议知识点；“从上下文推断”只能作为最后手段。

### 运行时考法画像

每个新项目都根据当前材料现场推导，不套用固定学科字典。

1. 扫描目录、标题、例题和习题，判断偏概念事实还是技能分析。
2. 结合学习场景和要贴合的考试题型。
3. 有样题先做样题风格提炼；没有样题则确认默认考法偏好与难度。
4. 输出考法家族、大致比例、干扰项来源、命题红线和难度基线。
5. 写入 `REQUIREMENTS.md` 的“考法画像”。
6. 首轮校准后按反馈修正。
7. 材料不足以判断时先问用户，不硬出。

## 出题执行

- 按知识点分组，同一知识点的题目集中排列。
- 干扰项来自真实、常见的错误理解，不能随机凑数。
- 错误选项与正确选项形式一致、语境合理、粒度相当。
- 优先保证单题质量；超大批量时分批出题，向用户提供当前批次路径并对照需求文档复核。
- 不确定知识点先要求权威来源；仍无法确认则避开。
- 高频知识点重复考查不等于必须去重。
- 修改题目时直接更新最终 Markdown 文件。

每道题成形前先判断主考法；必要时增加副考法。标签只用于命题和自查，默认不写入题库。
规则叠加顺序：通用命题底座 → 主考法 → 副考法补充。

## 通用命题底座

每道题都必须满足：

- 题干自足，不依赖材料原文也能独立作答。
- 答案唯一，无争议、无半对半错。
- 每个干扰项都有明确、可解释的排除依据。
- 同题选项字数极差不超过 6 字，句式与颗粒度相当。
- 不定项正确项数量有层次，默认目标 20% / 35% / 35% / 10%；可按学科和批次调整，
  但必须覆盖多种数量。
- 四项全选率不超过 10%，能设置可解释干扰项时优先不设全选。
- 20 道以上不定项批次，任一具体组合不超过 30%，A/B/C/D 都作为正确项出现。
- 不得跨题复用同一条选项正文；高度相似干扰项须改写。
- 术语与材料口径一致，不引入材料外定义。
- 难度符合基线，不能靠常识蒙对。
- 解析能独立证明答案，不写“略”“显然”。
- 题干否定词、限定词和范围词用 `**` 强调，单段控制在 2–3 处。
- 同一文件题干不得重复，否则题目 ID 冲突并共用作答记录。
- 不破坏 build.py 兼容的 Markdown 格式。

答案位置和具体组合由构建器均衡；正确项数量必须由命题决定。
含“以上都对”“上述各项”等位置敏感选项，或题干、选项、解析、知识标签引用
A/B/C/D 的题会安全跳过重排。

### 自动化分工

| 类别 | 内容 |
|:--|:--|
| 自动修复 | 单选答案位置、不定项具体组合 |
| 自动检测 | 正确项数量、全选率、组合集中度、字母覆盖、重复、相似度、长度、ID |
| 人工判断 | 干扰项语义、题干自足、答案唯一、解析充分、难度 |

构建会打印答案分布与审计。发布构建使用 `--strict-audit`；含位置敏感选项或
A/B/C/D 引用的题会跳过重排。

## 考法家族

| 考法家族 | 常见形态 | 干扰项来源 | 命题红线 |
|:--|:--|:--|:--|
| 记忆辨析 | 单选 / 判断 / 不定项 | 易混术语、人名、年代、词义 | 必须来自真实易混点 |
| 理解应用 | 情境题、翻译、句读、改错 | 语境误读、遗漏条件、过度泛化 | 题干信息必须充分 |
| 材料分析 | 看语料或案例选择结论 | 漏读条件、特征混淆、以偏概全 | 材料自足无歧义 |
| 计算推理 | 计算、推导判断 | 漏步、单位错误、公式错配 | 答案唯一且步骤可复核 |
| 流程操作 | 排序、步骤、标音、结构分析 | 步骤颠倒、遗漏、条件混淆 | 描述无二义 |
| 开放论述 | 简答、论述 | 不适用 | 给出采分要点；不用于建站题库 |

无法用三种建站题型承载的论述能力，建站时应拆成可解析考点；纯自测可不建站并保留
简答、论述和采分要点。

## 样题与首轮校准

有样题时必须先提炼并请用户确认：

1. 题型与题量结构；
2. 设问句式与信息量；
3. 选项长度、结构与粒度；
4. 干扰项模式；
5. 难度与区分度；
6. 答案与解析详略。

大批量前默认先出不超过 10 道校准题，请用户反馈难度、干扰项、真实考法和解析。
用户明确跳过时才可跳过。

## 输出结构

```text
<工作目录>/
├── REQUIREMENTS.md
└── 题库/
    ├── 模块一/
    │   └── 文件.md
    └── 模块二/
        └── 文件.md
```

`REQUIREMENTS.md` 必须在根目录，不能放入 `题库/`。文件名按用户简繁偏好直观命名。

题目格式必须是：

```markdown
### 第 N 题（单选题）

题干（ ）

A. 选项一
B. 选项二
C. 选项三
D. 选项四

**答案**：C

**解析**：说明答案依据和干扰项错因。

**知识回溯**：第一章·知识点
```

不定项答案使用 `A · B · D`；判断题无选项，答案为 `正确` 或 `错误`。

不定项示例：

```markdown
### 第 N 题（不定项选择题）

题干（ ）

A. 选项一
B. 选项二
C. 选项三
D. 选项四

**答案**：A · B · D

**解析**：说明每个正确项和错误项。

**知识回溯**：第一章·知识点
```

判断题示例：

```markdown
### 第 N 题（判断题）

题干（ ）

**答案**：错误

**解析**：说明判断依据。

**知识回溯**：第三章·知识点
```

## 批后复核

每批完成后逐项检查：

- 需求文档已冻结，当前批次符合范围、题型、题量、解析和回溯粒度；
- 答案字母有效、格式正确；
- 解析完整，知识回溯准确；
- 每个选项包含被考察对象并具有独立考察价值；
- 题干不暗示答案，也不绕弯考文字；
- 题干自足、答案唯一、干扰项可排除；
- 选项长度极差不超过 6 字；
- 不定项结构、组合和全选率达标；
- 已调用主考法和副考法对应规则；
- 无重复选项、重复题干或未闭合 Markdown；
- 复核结果写入 `REQUIREMENTS.md` 的“需求复核记录”。

发现偏离时先修正，不得继续下一批。
